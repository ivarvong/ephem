# ephem: agent notes

- Gate: `npm run typecheck && npm run lint && npm test` (the geodesic test needs `pyproj` on PATH). Accuracy bars are fixed.
- **Git (since 2026-10-29): trunk on `main`. Commit your finished change (only your files: `git add <paths>`, never `git add -A` in the shared tree), then deploy it with `scripts/deploy.sh main "<message>" [auto|ephem|tail|all]`.** Never run `cf deploy` directly (ephem or ephem-tail). deploy.sh takes a lock, refuses to go backwards (`ALLOW_OLDER=1` for a deliberate rollback), checks out the commit into a clean worktree, runs the full gate there, deploys ephem-tail first when packages/tail or src/routes.ts changed (`auto`) and verifies it with scripts/obs/tail-check.py, then ships ephem as a 0% canary smoked pinned (version-override header; `x-ephem-version` proves the version), promotes it, smokes it live, retries failed checks once, and otherwise **rolls back automatically** to the recorded previous version and exits 1 untagged. Success tags `deployed/<ts>` (and `deployed-tail/<ts>`). Smoke checks live in `scripts/smoke.sh` of the commit being deployed: add a check there with every new route. `DRY=1` runs the gate only. Rebase onto `main` before committing if another agent landed first. Continuous deploy is approved: ship whenever your commit is green. Details and measured timings: guide "Deploys".
- **Telemetry, traces and profiling: [docs/telemetry_and_profiling.md](docs/telemetry_and_profiling.md).** Measure by exact
  version id; every reported number carries its version and trace or profile. Update that guide in the same change
  whenever a command, span, attribute or gotcha changes.
- **One Worker (decided by A/B, 2026-10-30):** `ephem` = default (homepage, docs, MCP, live routes, weather, the search merge, Basin rows) + the cache-enabled `Api` and `BlockStore` (packages/worker/src/compute.ts) + MetarFeed + Admin, all called over `ctx.exports` through src/loopback.ts. A separate `ephem-compute` Worker behind service bindings was built, A/B-tested concurrently and removed (faster scans but +3 % CPU per scan, CI excluding 0; pre-registered rule). Don't re-split without a new A/B: DESIGN.md §12.0, guide "Compute split".
- MCP server at `/mcp` (src/mcp.ts, no deps; tools run the REST routes in-process). After every deploy run
  `node --experimental-strip-types scripts/obs/mcp-probe.ts https://ephem.ivar.workers.dev`; spans and attributes in the guide's MCP section.
- **Caching: Workers Cache only, never the Cache API (`caches.default`).** The default (eyeball) entrypoint has caching disabled and always runs (traces, logs, geolocation). It calls the cache-enabled internal entrypoints (`Api`, `BlockStore`, `MetarFeed`) via `ctx.exports`, and records their `cf-cache-status`. Measured (c72a360c): max-age=0 collapses concurrent misses (50 → 5 invocations) but runs the Api on every sequential request (+35 ms), so live "now" answers are computed in the front door, deterministic ones are `immutable`, weather is `max-age=0` + SWR. `crossVersionCache` is on (Worker-wide): every loopback key carries `CACHE_VERSION` (src/cache-version.ts), and every `ctx.exports` or service-binding fetch goes through src/loopback.ts (test/loopback.test.ts enforces it). **Changed a deterministic answer or a loopback response format? Bump CACHE_VERSION and run `npm run golden:record`** (test/golden.test.ts fails otherwise). Policy and numbers: docs/telemetry_and_profiling.md "Caching" (ivar, 2026-10-29).
- **Request logs: Basin** (stream `ephem_requests` → Iceberg `ephem.requests`; tail Worker `ephem-tail` (packages/tail) → `ephem.invocations`). One row per request from waitUntil, built from span attributes in src/requestlog.ts: never await it, never log raw query/path/UA/IP, round lat/lon to 0.01°. Stream schemas are immutable (packages/worker/ops/basin/*.schema.json). deploy.sh deploys ephem-tail before ephem whenever tailConsumers or the tail changes; ephem-tail's route labels come from packages/worker/src/routes.ts (one list with the request row). `python3 scripts/obs/basin.py failures|sql|crosscheck`; guide section "Request logs (Basin)".
- **Bundle:** import Effect by module subpath (`import * as Effect from "effect/Effect"`, `effect/http/HttpRouter`), never from a barrel (`"effect"`, `"effect/http"`, `"effect/http-api"`): a barrel import keeps the whole module (test/imports.test.ts enforces it). The EGM96 grid is not bundled: bands come from R2 `ephem-geoid` (src/geoid.ts; guide "Geoid bands"). Never write to `ephem-de440`.
