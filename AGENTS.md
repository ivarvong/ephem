# ephem: agent notes

- Gate: `npm run typecheck && npm run lint && npm test` (the geodesic test needs `pyproj` on PATH). Accuracy bars are fixed.
- **Shipping (since 2026-10-31; ivar: "Ship every commit fast"): just commit small, green commits to `main`. `scripts/ship.sh` (a detached watcher; `scripts/ship.sh status|stop|start|log|retry`) deploys every new main through deploy.sh within ~2 s of the commit, coalescing commits that land during a deploy into the next one (the newest main contains them all). Don't run deploy.sh yourself for a normal change; verify on prod by version id instead: `scripts/ship.sh log` (or ~/code/lab_notebook/ephem-ship.log) names the version that shipped your sha, and `x-ephem-version` on any prod response must equal it (pinned checks: `cloudflare-workers-version-overrides: ephem="<id>"`). The live verdict (rollback is automatic) follows ~105 s after promotion as a `live <sha> <ver> ok|ROLLED-BACK` line. A failed head blocks main (notification + `FAILED` line) until a newer commit passes: fix forward with a new commit, never by amending/rewriting main. Main must stay green: run the gate before committing. A UI change ships on commit, so its UI acceptance (below) is done before the commit, locally or on a pinned 0% version, not after.**
- **Git (since 2026-10-29): trunk on `main`. Commit your finished change (only your files: `git add <paths>`, never `git add -A` in the shared tree); ship.sh deploys it. `scripts/deploy.sh main "<message>" [auto|ephem|tail|load|all]` stays for manual use (ship.sh stopped, a target ship.sh does not cover, `ALLOW_OLDER=1` rollbacks); it takes the same lock, so it refuses while ship.sh deploys.** deploy.sh is two-stage: the shared-tree copy only takes the lock, checks never-backwards, makes the worktree and execs **the commit's own** scripts/deploy.sh, so deploy logic, smoke.sh and the gate always come from the commit (never edit deploy tooling in the shared tree to change a running deploy; commit it; replace the shared bootstrap only by an atomic `mv`). Never run `cf deploy` directly (ephem or ephem-tail). deploy.sh takes a lock, refuses to go backwards (`ALLOW_OLDER=1` for a deliberate rollback), checks out the commit into a clean worktree, uploads the version while it runs the gate there (typecheck, lint and tests in parallel; a tree that already passed with the same node_modules is skipped), deploys ephem-tail first when packages/tail or src/routes.ts changed (`auto`) and verifies it with scripts/obs/tail-check.py, then routes ephem 0% as a canary smoked pinned (version-override header; `x-ephem-version` proves the version; checks run concurrently), runs the **telemetry gate** (scripts/obs/canary-gate.py: the smoke's own requests in Workers Observability, by `x-ephem-smoke` header and cf-ray; exceptions, 5xx, error/`*_failed` logs, missing entrypoints/spans or missing telemetry remove the canary; it passes early at 0 errors + every required span + 75% of the requests visible), promotes it, smokes it live and is **done** (tagged `deployed/<ts>`, ~45 s after start). A detached **live watcher** then re-runs the canary gate in full, gates the live smoke + 90 s of real traffic and runs the tail check, and on any failure **rolls back automatically** to the recorded previous version, deletes the tag and notifies; the next deploy waits for its verdict (`.git/ephem-live.lock`; log and verdict in `.git/ephem-live/`). `LIVE_WAIT=1` keeps the watcher in the foreground. Smoke checks live in `scripts/smoke.sh` of the commit being deployed: add a check there with every new route. `DRY=1` runs the gate only. `SKIP_O11Y_GATE=1` only in an emergency. Never count o11y events by `$metadata.id` (not unique; guide "Gotchas"). Rebase onto `main` before committing if another agent landed first. Details: guide "Ship and roll back"; measured timings: guide "Current numbers".

- **One Worker (decided by A/B, 2026-10-30):** `ephem` = default (homepage, docs, MCP, live routes, weather, the search merge, Basin rows) + the cache-enabled `Api` and `BlockStore` (packages/worker/src/compute.ts) + MetarFeed + Admin, all called over `ctx.exports` through src/loopback.ts. A separate `ephem-compute` Worker behind service bindings was built, A/B-tested concurrently and removed (faster scans but +3 % CPU per scan, CI excluding 0; pre-registered rule). Don't re-split without a new A/B: DESIGN.md §12.0; the A/B is in ~/code/lab_notebook/ephem-telemetry-history-2026-10-31.md.
- **Load: drive it from Cloudflare, not the laptop** (since 2026-10-30): `node --experimental-strip-types scripts/obs/load-remote.ts --mode mixed --rate 60 --duration 60 --regions enam,weur,apac [--pin ephem=<id>]` runs open-loop load from the `ephem-load` Worker's Generator Durable Objects (packages/load) and prints a per-region client table; `python3 scripts/obs/load-check.py load-runs/<run>.json` checks it against server spans. Every request carries `x-ephem-load: <run>` (request rows: `synthetic = true`). Caps (rate, duration, scans, one run at a time, hourly budget; target fixed to prod) are in packages/load/src/workload.ts. Deploy it with `scripts/deploy.sh main "…" load`. Guide section "Load".
- MCP server at `/mcp` (src/mcp.ts, no deps; tools run the REST routes in-process). After every deploy run
  `node --experimental-strip-types scripts/obs/mcp-probe.ts https://ephem.ivar.workers.dev`; spans and attributes in the guide's MCP section.
- **Caching: Workers Cache only, never the Cache API (`caches.default`).** The default (eyeball) entrypoint has caching disabled and always runs (traces, logs, geolocation). It calls the cache-enabled internal entrypoints (`Api`, `BlockStore`, `MetarFeed`) via `ctx.exports`, and records their `cf-cache-status`. Measured (c72a360c): max-age=0 collapses concurrent misses (50 → 5 invocations) but runs the Api on every sequential request (+35 ms), so live "now" answers are computed in the front door, deterministic ones are `immutable`, weather is `max-age=0` + SWR. `crossVersionCache` is on (Worker-wide): every loopback key carries `CACHE_VERSION` (src/cache-version.ts), and every `ctx.exports` or service-binding fetch goes through src/loopback.ts (test/loopback.test.ts enforces it). **Changed a deterministic answer or a loopback response format? Bump CACHE_VERSION and run `npm run golden:record`** (test/golden.test.ts fails otherwise). Policy and numbers: docs/telemetry_and_profiling.md "Caching" (ivar, 2026-10-29).
- **Request logs: Basin** (stream `ephem_requests` → Iceberg `ephem.requests`; tail Worker `ephem-tail` (packages/tail) → `ephem.invocations`). One row per request from waitUntil, built from span attributes in src/requestlog.ts: never await it, never log raw query/path/UA/IP, round lat/lon to 0.01°. Stream schemas are immutable (packages/worker/ops/basin/*.schema.json): a schema change replaces the stream in place, same name (`basin.py teardown` → `create-streams` → `provision` → deploy; guide), never a `_v2`. deploy.sh deploys ephem-tail before ephem whenever tailConsumers or the tail changes; ephem-tail's route labels come from packages/worker/src/routes.ts (one list with the request row). `python3 scripts/obs/basin.py failures|sql|crosscheck`; guide section "Request logs (Basin)".
- **Bundle:** import Effect by module subpath (`import * as Effect from "effect/Effect"`, `effect/http/HttpRouter`), never from a barrel (`"effect"`, `"effect/http"`, `"effect/http-api"`): a barrel import keeps the whole module (test/imports.test.ts enforces it). The EGM96 grid is not bundled: bands come from R2 `ephem-geoid` (src/geoid.ts; guide "Geoid bands"). Never write to `ephem-de440`.

- **UI acceptance (ivar, 2026-10-30; a UI is not done until all hold, checked by looking, not inferred):** (1) every state rendered and looked at — for the sky: day, each twilight, night Moon up/down, body at horizon, polar day/night, southern hemisphere, near-zenith — at 390×844 and 375×667, light and dark, plus desktop; a contact sheet in the report; (2) no dead space: every region shows data in every state, height fits content; (3) one design system across the whole page (mission-ops + RPN Instrument, dark-first; light is a variant of the same system, never a dark card on a light page), full bleed where it is the hero; (4) no collisions: labels vs paths/markers/labels, tested by bounding boxes; (5) live: values, clocks and countdowns move; staleness visible; no idle rAF loop; (6) a journey trace (`scripts/obs/journey.ts`, iPhone fast3g cpu4 + desktop, cold + warm): critical path, request count, data drawn, no regression — and verify that anything named on the critical path is actually waited on; (7) compared against a real iPhone screenshot before calling it done. The coordinator reviews the screenshots against this list before reporting.
- **Telemetry and trace visuals render only what was recorded (ivar, 2026-10-31: "the trace is a total lie").** Every bar/marker/number must come from recorded timestamps (CDP event, server span, RUM entry, invocation event), offset applied with its ± shown. Never cap, infer, or fall back to fill an unknown and present it as fact: show "not recorded". Derived values are labelled derived. Reviewers check each element's source.
- **Prerelease: versions yes, backward compatibility no (ivar, 2026-10-31).** The API is /v1 and we iterate on v1 in place, breaking it freely until it is declared stable; replace schemas, streams and formats in place; no `_v2`, dual writes, aliases, redirects, staged migrations or readers for old formats. Cache-invalidation keys are fine.
